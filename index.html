What is Splunk?

Splunk is a SIEM and log analysis platform used by SOC analysts, security engineers, and threat hunters to search, analyze, and investigate machine-generated logs.

⚠ Analyst Insight

Think of Splunk as Google for your infrastructure and security logs. Strong search logic directly improves investigations.

Understanding Splunk Architecture

Forwarder

Collects logs from endpoints and sends them to the Indexer.

Indexer

Processes and stores logs while handling search operations.

Search Head

Used by analysts to perform searches, create dashboards, and investigate alerts.

SPL Fundamentals

index=wineventlog EventCode=4625 | stats count by user, src_ip

Detects repeated failed login attempts and possible brute-force attacks.

🎯 IRL SOC Workflow

Analysts investigate IP reputation, MFA activity, user history, and authentication timelines.

Search Processing Language (SPL)

Search Processing Language (SPL) is the core language used inside Splunk for searching, filtering, transforming, and analyzing logs. Understanding SPL is one of the most important skills for SOC analysts, threat hunters, and detection engineers.

Task 1 — Search & Reporting

Learn how to search indexes, retrieve events, and build reports from machine-generated logs.

index=main

Task 2 — Search Operators

Use Boolean operators like AND, OR, and NOT for advanced filtering and precise searches.

index=main error OR failure

Task 3 — Filtering Results

Filter unnecessary noise and focus only on relevant events during investigations.

index=main status=failed

Task 4 — Structuring Results

Structure results using commands like table, fields, rename, and sort.

| table user src_ip EventCode

Task 5 — Transforming Commands

Transform raw logs into meaningful statistics and visualized information.

| stats count by user

Task 6 — Anomaly Detection

Detect unusual behaviors, spikes, suspicious patterns, and abnormal activity across systems.

| rare process_name

Important Windows Event IDs

4624 — Successful Login

Tracks successful authentication events.

4625 — Failed Login

Useful for brute-force detection and password spraying analysis.

4688 — Process Creation

Critical for identifying suspicious processes and malware execution.

4104 — PowerShell Logs

Captures PowerShell execution activity.

7045 — Service Installed

Detects malicious service installation attempts.

4720 — User Account Created

Helps identify unauthorized account creation.

Threat Hunting Basics

Rare Processes

index=wineventlog EventCode=4688 | rare process_name

Find uncommon processes running inside the environment.

Suspicious Parent-Child Relationships

parent_process="WINWORD.EXE" process_name="powershell.exe"

Detects suspicious Office-to-PowerShell execution chains.

Encoded PowerShell

powershell.exe "*EncodedCommand*"

Detects obfuscated PowerShell commands.

Detection Engineering

False Positives

Not every alert is malicious. Detection tuning is essential.

Correlation

Strong detections combine process logs, authentication logs, and network activity.

Detection Lifecycle

Hypothesis → Testing → Tuning → Deployment → Monitoring.

MITRE ATT&CK Framework

T1059 — Command Execution

Attackers execute malicious commands using PowerShell or CMD.

T1110 — Brute Force

Repeated password attempts against accounts.

T1547 — Persistence

Maintaining access after reboot or logout.

T1021 — Remote Services

Using RDP, SMB, SSH, or WinRM for lateral movement.

SOC Investigation Workflow

1. Alert Validation

Determine whether the alert is legitimate.

2. Context Gathering

Collect user, hostname, IP, and process details.

3. Correlation

Correlate authentication, process, DNS, and network logs.

4. Escalation

Escalate confirmed malicious activity to IR teams.
